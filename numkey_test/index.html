숫자 입력 방식 실험실

입력칸마다 숫자가 들어올 때 크롬이 어떤 이벤트를 함께 전달했는지 기록합니다. 같은 칸을 삼성 키보드와 M키보드로 번갈아 입력해 비교하세요.

이 페이지가 보는 것은 크롬의 웹 이벤트입니다. 키보드가 안드로이드에서 어떤 함수를 불렀는지는 직접 알 수 없고, 이벤트 모양으로 추정할 뿐입니다.

판정 기준 보기
숫자 키 이벤트 동반keydown key="1" → input data="1"수정키 없이 누른 숫자 키의 keydown이 먼저 오고, 들어온 글자가 그 숫자와 같음. 키보드가 숫자 키 이벤트를 보냈을 가능성이 큼
IME 처리 키 이벤트 동반keydown keyCode=229 / Unidentified / Process → input입력기 처리 표시만 옴. 키보드가 글자를 바로 넣었을 가능성이 큼 (함수는 확정 못 함)
키 이벤트 없이 삽입input만 옴keydown 없이 값이 바뀜
판정 불가 · 붙여넣기data 없음 / 숫자 아닌 키·수정키 / 키와 글자 불일치 / insertFromPaste위 셋 중 하나로 단정하지 않음
삽입 미관찰 · 길이 제한 추정숫자 keydown → (input 없음) → keyup값이 그대로임. 길이가 가득 찬 칸이면 길이 제한으로 추정하고, 그 밖에는 원인을 단정하지 않음
모형: 거부·막힘점선 칸모형 칸이 일부러 거부하거나 막은 입력

시험 순서

  1. "지금 키보드"에 키보드 이름을 적습니다.
  2. 모든 칸에서 1 2 3 4를 한 번씩 누릅니다.
  3. 최대 2자리 칸: 2단계 뒤 남아 있는 12를 길게 눌러 전체 선택하고 3을 누릅니다. 다시 입력하지 마세요.
  4. "결과 복사"를 누르고 복사한 내용을 메모 등에 따로 보관한 뒤, "모두 지우기"를 누르고 다른 키보드로 같은 순서를 반복합니다.

횟수는 관찰된 삽입 이벤트, 삽입이 관찰되지 않은 숫자 키 이벤트, 모형 칸이 처리한 숫자 키 이벤트를 센 값입니다. 숫자를 한 번씩 누르는 비교용이라 여러 키를 동시에 누르면 정확히 세지 않습니다. 실제로 누른 횟수와 다를 수 있으니 기록과 최종 값을 함께 보세요.

전체 이벤트 기록 (최신이 위)

웹페이지에서는 크롬이 받은 결과만 보입니다. 앱의 시간 선택 부품 같은 기본 부품은 똑같이 만들 수 없어서, 점선 칸은 원리만 보여 주는 모형입니다. 키보드가 받는 칸 종류(안드로이드 EditorInfo.inputType)는 이 페이지에서 알 수 없으니 M키보드 진단 기록에서 확인하세요. 기록의 inputType은 웹 이벤트의 값이라 다른 것입니다. type="time"은 크롬에서 키보드 대신 선택 창이 떠서 넣지 않았습니다.
